# Apex Solutions --- Website Design System

> **Reference basis:** The attached website screenshot is used only to
> study its visual language, typography hierarchy, spacing, section
> composition, UI density, and motion/effect direction.\
> **Brand basis:** Apex Solutions official logo palette --- Deep Navy
> `#081E42` and Apex Gold `#D7AB11`.
>
> **Important:** Do not copy the reference website's branding, content,
> illustrations, layouts, or assets. Recreate the *design quality and
> visual principles* using Apex Solutions' own identity.

------------------------------------------------------------------------

## 1. Design Direction

### Core aesthetic

Apex Solutions should feel like a:

-   Premium technology engineering company
-   Enterprise software partner
-   AI and digital transformation company
-   Modern product engineering studio
-   High-trust B2B technology brand

### Visual keywords

`Minimal` · `Editorial` · `Technical` · `Premium` · `Confident` ·
`Clean` · `Human` · `Engineering-led`

The reference uses a restrained visual system rather than a highly
decorative SaaS template. Apex should preserve that restraint.

### Avoid

-   Generic SaaS dashboard templates
-   Excessive glassmorphism
-   Excessive gradients
-   Heavy shadows
-   Too many rounded cards
-   Excessive gold
-   Stock-photo-heavy layouts
-   Icon overload
-   Large decorative 3D objects in every section
-   Neon cyberpunk styling
-   Excessive animations
-   Dense navigation

# 4. Typography

## 4.1 Recommended font system

### Primary UI / Body

**Inter**

Use for:

-   Navigation
-   Body copy
-   Buttons
-   Labels
-   Forms
-   Metrics
-   Cards
-   Footer

### Alternative

**Manrope**

Use if a slightly softer, more contemporary geometric appearance is
preferred.

### Editorial display option

For selected hero statements or section headlines:

**Instrument Serif** or **DM Serif Display**

Use sparingly.

The reference relies primarily on a clean sans-serif system. Serif
should therefore be an Apex enhancement, not the dominant font.

# 6. Typography Rules

### Headlines

-   Short
-   Strong
-   2--4 lines maximum
-   High contrast
-   Generous surrounding whitespace
-   Avoid paragraphs disguised as headings

### Eyebrows

Use small uppercase labels such as:

`WHAT WE BUILD`

`OUR CAPABILITIES`

`ENGINEERING APPROACH`

Use letter spacing around `0.08em–0.14em`.

### Body copy

Keep line length approximately:

`45–70 characters`

Avoid large blocks of text.

------------------------------------------------------------------------

# 7. Layout System

## Grid

Use a responsive 12-column grid.

Desktop:

-   Max width: `1440–1520px`
-   Horizontal padding: `48–80px`

Tablet:

-   Horizontal padding: `32–48px`

Mobile:

-   Horizontal padding: `20–24px`

## Vertical rhythm

Prefer large section spacing:

Desktop: `120–180px`

Large editorial sections: `160–220px`

Mobile: `80–120px`

The reference feels premium largely because of whitespace.

------------------------------------------------------------------------

# 8. Section Composition

Do not make every section a card grid.

Use a mix of:

1.  Full-width statements
2.  Split editorial layouts
3.  Bento/grid sections
4.  Dark metric sections
5.  Horizontal storytelling
6.  Image + text compositions
7.  Timeline/process sections
8.  Testimonials
9.  Case studies
10. Large CTA sections

Every section should have a different visual rhythm while still using
the same design system.

# 18. Motion Design

## Core technology

-   GSAP
-   ScrollTrigger
-   Lenis

## Motion principles

Motion should reveal information rather than decorate the page.

### Text reveal

Use line-by-line or word-group reveal.

Suggested:

-   Y movement: `20–40px`
-   Opacity: `0 → 1`
-   Duration: `0.6–1.0s`
-   Ease: `power3.out`

### Image reveal

Use:

-   Clip-path
-   Scale from `1.05 → 1`
-   Opacity

### SVG

Animate:

-   Path drawing
-   Node activation
-   Connection flow

### Scroll

Use:

-   Pinning
-   Parallax
-   Scale
-   Mask reveals
-   Horizontal movement

Avoid excessive scroll-jacking.

------------------------------------------------------------------------

# 19. Hover Effects

### Navigation

Underline expands from left to right.

### Images

Scale: `1 → 1.03`

### Cards

Subtle lift.

### Buttons

Magnetic movement: `4–8px`

### Engineering nodes

Node grows slightly and activates connected lines.

### Gold accent

Use gold as the visual response to interaction.

------------------------------------------------------------------------

# 20. Cursor

Desktop only.

Create a minimal cursor follower.

Default: small navy/gold dot.

On interactive element:

-   Expand
-   Change border
-   Display short label such as `VIEW` or `OPEN`

Disable custom cursor on:

-   Touch devices
-   Reduced-motion preference

------------------------------------------------------------------------

# 21. Scroll Progress

Minimal vertical progress indicator.

Position:

Right side of viewport.

Color:

`#D7AB11`

Background:

`rgba(8,30,66,0.12)`

Keep it extremely subtle.

------------------------------------------------------------------------

# 22. Accessibility

Respect:

`prefers-reduced-motion`

When reduced motion is enabled:

-   Remove parallax
-   Remove cursor follower
-   Remove excessive transforms
-   Keep simple opacity transitions

Maintain:

-   WCAG AA contrast
-   Keyboard navigation
-   Visible focus states
-   Semantic HTML
-   Accessible buttons
-   Accessible forms

------------------------------------------------------------------------

# 23. Responsive Behavior

-   Semantic headings
-   One clear H1
-   Descriptive H2 sections
-   Structured service descriptions
-   FAQ section
-   Organization schema
-   Service schema
-   Breadcrumb schema where relevant

# 28. Performance Targets

Target:

-   Lighthouse Performance: `90+`
-   Accessibility: `95+`
-   Best Practices: `95+`
-   SEO: `95+`

Maintain smooth animation at approximately 60 FPS on modern devices.

Prefer:

-   `transform`
-   `opacity`
-   GPU-friendly animation
-   Lazy-loaded media
-   Optimized WebP/AVIF
-   Dynamic imports
-   Reduced animation on low-power/mobile devices

Avoid layout-triggering animation such as frequent animation of:

-   `top`
-   `left`
-   `width`
-   `height`

------------------------------------------------------------------------

# 29. Final Visual Rule

The website should NOT look like:

"Another IT company website."

It should look like:

**A premium engineering company that happens to have a website.**

The visual hierarchy should be:

**Typography → Story → Engineering Visuals → Motion → Color → UI**

Not:

**Cards → Icons → Gradients → Buttons**

Apex Navy establishes authority.

Apex Gold creates moments of attention.

White space creates premium perception.

GSAP creates continuity.

Engineering graphics create identity.

Typography creates confidence.
